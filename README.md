# s21-paks

Build recipes for the RPaks of the R5Flowstate S21 bridge: the S21 client
paks in `paks/Win64/` and the S3 dedicated-server paks in
`paks/Win64_server/`. Each pak is described by a Repak manifest that lists
every asset it packs, pinned by GUID, and a build list that groups manifests
into one Repak run.

The custom and SDK content paks (`common_flowstate`, `sdk_s30`, Axle, the
overdrive gcards, `ui_sdk`) ship with their input assets in this repo, so
they build straight from a clone. The map paks do not: their inputs are
extracted from your own game install into the workspace the manifest names.
Built `.rpak` / `.starpak` files are never committed.

## Layout

| path | contents |
|---|---|
| `build_list_s21_dedi.json` | The full dedi set in one Repak run. |
| `build_list_<pak>_only.json`, `build_list_<pak>_dedi.json` | Rebuild a single dedi pak. |
| `build_list_s21_cli.json` | The district client set (base + perm + temp). |
| `s21-to-s3-server/` | Dedi manifests, one per pak. Server asset types only: `mdl_` `aseq` `arig` `stgs` `stlt` `dtbl` `txls` `Ptch`. |
| `s21-maps/<map>/` | Client map manifests: `mp_rr_district_mu1`, `mp_rr_district`, `mp_rr_aqueduct`, `mp_rr_arena_composite`, `mp_rr_arena_skygarden`. |
| `s21-flowstate/` | `common_flowstate` client manifest and its dedi twin. |
| `s30_unified/` | `sdk_s30` and `sdk_s30_dedi`, the merged SDK content paks, with their build lists. Inputs under `s30_axle/paks_out/assets_axle/`, `s30_efct_port/out_axle/`, `s30_akimbo/`. |
| `s30_axle/paks_out/` | Axle character paks and the overdrive skin root, with inputs in `assets_axle/` and `dedi_assets/`. |
| `s30_overdrive/gcard_frames/` | Overdrive gcard frame paks and their `uiia` inputs. |
| `s21-ui/ui_sdk/` | `ui_sdk` (uiia set) and its inputs. |
| `docs/MANIFESTS.md` | Every manifest with its asset counts by type, starpak names and build-list membership. Generated by `tools/manifest_index.py`. |
| `docs/ASSET_SOURCES.md` | Donor build and converter per pak, plus the tool pins. |
| `AGENTS.md` | Working notes for the port pipeline: versions, order, gates, traps. |

All paths inside manifests and build lists are relative to the repo root
(`assetsDir: ./s21-maps/<map>/assets/`, `outputDir: ./paks/Win64/`). Run
Repak from the repo root.

## Tools

| tool | use |
|---|---|
| [RePak](https://github.com/R5Flowstate/RePak) | builds a pak from a manifest; the `dedi` build-list flag targets the S3 server |
| [rsx](https://github.com/R5Flowstate/rsx) | extracts assets from a donor install into `assetsDir` |
| [rmdlconv](https://github.com/R5Flowstate/rmdlconv) | model version conversion (`mdl_` v19 to v17 for the client, to v10 for the dedi) |
| [R5-AnimConv](https://github.com/R5Flowstate/R5-AnimConv) | `aseq` / `arig` conversion |
| [bspconv](https://github.com/R5Flowstate/bspconv) | map BSP conversion (v52 to v51 client, v47 dedi) |

Commit pins are in `docs/ASSET_SOURCES.md`.

## Building a pak

Custom and SDK paks: from the repo root, `repak.exe s30_unified/build_list_client.json`
(or the dedi list). The inputs are already in place.

Map paks:

1. Read the pak's row in `docs/ASSET_SOURCES.md` for its donor build.
2. Extract the assets the manifest names from that build with rsx into the
   manifest's `assetsDir`.
3. Convert what the target engine cannot load as-is: models with rmdlconv,
   animations with R5-AnimConv.
4. From the repo root: `repak.exe build_list_<x>.json`. Output lands in the
   build list's `outputDir`.
5. Copy the result into `paks/Win64/` (client) or `paks/Win64_server/`
   (dedi) of the install.

Each client map pak owns a streaming pair, `pc_all_<map>.starpak` and
`pc_all_<map>.opt.starpak`, named in its manifest. Rebuilding a map
rewrites its pair.

## Regenerating the index

    py -3 tools/manifest_index.py
